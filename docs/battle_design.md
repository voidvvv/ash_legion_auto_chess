## 二、主循环（H 语义）

```
每个逻辑 tick（60Hz，固定序；五阶段——弹道推进为实现层口径 #2 插入，2026-09-02 回填同步 spec_plan 差异表）：
① 状态推进：DOT 心跳结算（可致死，直接进清扫名单）、持续时间递减、控制倒计时
② 弹道推进：锁定弹追踪 / 非锁定弹直线飞行，到达按冻结载荷结算（先落地——后行动者看到最新血量）
③ 逐单位行动（id 升序；跳过"已在清扫名单"的单位）——攻击/移动计时器先全体恒累计（口径 #4 恒累计半句，与射程无关），再逐单位决策：
     被控制（存在任一控制类状态） → 跳过
     目标失效（=已被标记死亡）   → findTarget()
     能量 ≥ 100                  → 就地施放技能（在能量过百的结算点内）
     目标在射程内（曼哈顿 ≤ range）→ 攻击计时到点出手（发射/结算，取模结转余数）
     否则                        → 跳格冷却就绪则走一步
④ 死亡清扫：统一标记死亡、腾格（预留亡语/掉落钩子）
⑤ 胜负 / 超时（60s）判定
```

**关键语义**：
- **伤害立即落地**：结算点当场扣 HP，后行动者看到的是最新血量（HEAL 能奶到本 tick 刚被打残的人）
- **死亡延迟清算**：HP ≤ 0 但尚未清扫的单位在本 tick 仍是合法目标、仍可行动——互秒与“濒死反打”自然发生
- **同 tick 冲突一律由固定遍历序 + id 决胜**：确定性回放的根基

### 开战转场「清场入阵」（2026-09-09 修订，取代 2026-09-02 倒计时案）

**是什么**：点击开战进入 BATTLE 后先播 **0.6 秒（待调，区间 0.4~0.8）清场转场**——备战 UI 滑出屏幕、战斗 HUD 落位、棋盘镜头轻微回正，敌阵侦察虚影实体化（敌军亮相一拍），逻辑完全冻结；转场结束后攻击/移动计时器**从零开始蓄力**，上方五阶段主循环由此起步。已在射程内的单位首刀因此天然延后一个完整攻击间隔——紧张感由「**清场空拍 + 蓄力条充能 + 首刀延后**」承担（修订理由：倒计时仪式感换成场效率与紧张感重构，用户看过动效分镜后裁决）。

**流程**：`startBattle` 派生完成（发号 / 布阵 / 基准快照 / 开局效果 / 初始索敌，全部不变）→ **清场转场 0.6s** → 归零 → `step` 主循环；战毕回备战（RESULT→SHOPPING）播**反向同款转场**（商店栏上滑回位、战斗 HUD 上升退场、备战席/背包滑回、镜头复位——Q3 已定 2026-09-09；方向为 Q6 勘误后口径）。分镜图：`docs/diagrams/battle_intro_slide_transition.md`（配 .html 三帧分镜 + 动效演示；取代已废弃的 `battle_intro_countdown.md`）。

**冻结清单（转场期间一律不推进；机制原样复用 2026-09-02 的 intro 冻结门控，仅时长 3s→0.6s）**：
- `BattleSystem.step` 整体不调用——elapsed 不累计，**60s 超时判负时钟不从转场起表**（超时仍在 step ⑤ 判定，GDD §6.4 的 60s 只数主循环时长）
- 攻击/移动计时器保持 0（构造即归零，见 §5.1 修订）——已在射程内单位的首刀 = 转场结束后再等 1/(attackSpeed × 0.6) 秒（攻速 1.5 → 1.11s；0.7 → 2.38s）；走位中的单位计时器同步蓄力（恒累计），到达即出手
- 能量、DOT/REGEN 心跳、状态时长全部冻结（开局 SHIELD 为 ∞ 时长，无影响）
- 零 RNG 消耗、零 CombatEvent 产出——转场是纯表现阶段，确定性回放不包含它
- **输入禁用**：转场期棋盘与 UI 输入一律不响应——镜头回正不影响 unproject 命中换算（转场期本就无输入可命中）

**转场动作表（0~0.6s 内完成；区域编号与坐标沿用 render §九，动作细则与驱动规格见 render §5.6）**：

| 元素（域） | 动作 |
|---|---|
| 商店栏 ⑧（UI，实机底部） | **下滑离场**（屏幕下缘；反向**上滑回位**。Q6 勘误：实机渲染在底部 0..64 条带，render §九 ⑧ 表值 (0,296,640,64) 与代码漂移属既有问题） |
| 战斗 HUD（UI，实机顶部） | 自屏幕上缘外**下落就位**（反向**上升退场**；BATTLE 期常驻顶部，**不接管任何槽位**——「交接同一槽位」表述废弃，两屏缘各自进出，观感 = 经营层/战斗层整层交换；决策 #4 静态语义不变——⑧ 仅 SHOPPING、HUD 仅 BATTLE 照旧） |
| 开战按钮 ⑥（UI） | 左移淡出 |
| 出售区 ⑦（棋盘域）+ 布阵提示 | 淡出 |
| 备战席 ②（棋盘域）+ 背包 ③（UI） | **左滑离场**（Q1 裁决「滑出」——render §九 ②③ 阶段可见性由「全程、战斗期置灰」修订为「仅 SHOPPING，随转场离场」） |
| 羁绊面板 ⑤（UI） | 原地置暗保留（羁绊是战斗相关信息，清场不清它） |
| 通知 ⑨ / 顶栏 | 不动 |
| 棋盘 ④（棋盘域） | **镜头轻微回正 zoom 1.06→1.0**（Q4 保留，「聚焦战场」一拍）；**敌阵侦察虚影实体化 = 敌军亮相一拍** |

**表现**：动作表见 render §5.6（UI 域 actor 位移/淡入出 + 棋盘域镜头插值，纯表现）；倒计时横幅（`render/ui/BattleIntroBanner.java`）**退役删除**，原「横幅不拦截输入」条随之作废、代之为转场期全量输入禁用。原倒计时案缺陷 W2「零棋子局白等 3s」随横幅废弃自然消失（转场照播，无空等感）。

**快进交互**：×2 快进（`GameBalance.BATTLE_SPEED_FACTOR_FAST`，只乘 accumulator 消费速率，`BattleScreen.java:403`）作用于同一逻辑步通路——**转场同步 ×2 加速**，无特判。

**实现落点**：机制复用既有 `BattleState.introRemaining` 冻结门控（`beginIntroCountdown / advanceIntroCountdown / isIntroCountdownActive`，`entities/BattleState.java:29,93-142`——2026-09-02 实现落点二选一中的方案 ② 已落地）——时长改由转场常量提供（暂名 `BATTLE_INTRO_TRANSITION_SECONDS`，取代 `BATTLE_INTRO_COUNTDOWN_SECONDS`；终名由实施计划定），`BATTLE_INTRO_GO_BEAT_SECONDS` 随横幅一并废弃；转场驱动器（actor 位移/淡入出 + worldCamera zoom 插值）与反向转场触发点由实施计划细化。

### CombatEvent 事件流

每个结算点记录纯数据事件（type / tick / sourceId / targetId / amount / 附带标志）：

| 事件 | 触发点 |
|------|--------|
| `AttackLaunched` | 近战出手 / 弹道发射（含载荷快照） |
| `Hit` | 伤害落地（含 isCrit、实际伤害、双方能量变化） |
| `Cast` | 技能施放（skillId、sourceId、**主目标 targetId**——无弹道技能的区域特效中心） |
| `StatusApplied` | 状态挂载/刷新（type、时长、power） |
| `Healed` / `Shielded` | 治疗与护盾落地 |
| `UnitDied` | 死亡清扫 |
| `ProjectileFizzled` | 弹道落空/消散 |
| `BattleEnded` | 胜负/超时 |

- 事件对象建议池化复用（60Hz × 事件量的 GC 压力控制）
- 逻辑层**只产出**事件；渲染层消费事件驱动动画与飘字——逻辑/表现彻底解耦
- 消费者：FxLayer（特效，render §5.3/5.4）、FloatingText（飘字）、**NotificationPanel（战斗日志，render §5.5 第三消费者）**；测试断言与回放复盘为第四用途——同一份事件流，零复制

## 三、AI：优先链决策（非行为树）

每 tick 每单位走一条固定优先链（纯函数，≤ 50 行；gdx-ai 留给未来 Boss 脚本）：

```
被控制? → 跳过
目标有效? → 无效则 findTarget()
能量满?  → 施放技能
射程内?  → 攻击
否则     → 移动一步
```

### 索引细则（findTarget）

在存活敌方（含濒死未清扫）中按优先级排序：

| 优先级 | 排序键 | 平局决胜 |
|--------|--------|----------|
| `NEAREST` | min 曼哈顿距离(自身, 敌) | id 升序 |
| `BACKLINE` | max 纵深（敌方单位到缓冲行第 3 行的距离） | 距离最近 → id |
| `LOWEST_HP` | min currentHp / maxHp | 距离 → id |
| `HIGHEST_ATK` | max 当前有效攻击力 | 距离 → id |

所有排序末位都是 **id 决胜**——确定性的最后一道保险。

### 重评估节奏（已定：非粘滞）
- **目标死亡（被清扫）→ 立即重选**
- **每 2 秒（120 tick）全局统一强制重评估**，按 id 序执行，结果可能不变
- `LOWEST_HP` / `HIGHEST_ATK` 类索敌因此会切火——已接受的已知行为

### 状态机的取舍（为什么逻辑层不用 FSM）

**先区分两种"状态"**：

| | 状态（数据） | 行为（决策） |
|---|---|---|
| 是什么 | "被眩晕了"——一个事实 | "本 tick 干什么"——事实的推论 |
| 存在哪 | `ActiveStatus` 列表（时长/来源/叠加规则） | 不存储，每 tick 由决策链现推 |

普通棋子的全部候选行为状态（ATTACK / MOVE / CAST / STUNNED / DEAD）要么可由事实直接推导（射程∧冷却→攻击），要么本就是别处的数据（清扫名单、状态列表）——**FSM 无记忆可管**。

**不用的四条理由**：
1. **双账本**：状态系统已是唯一事实源，FSM 状态只是第二份拷贝，每 tick 都要同步一次；
2. **失同步 bug 类**：依赖事件回调进/出状态，一旦丢失或时序错位，出现"显示眩晕却在动"的幽灵 bug；谓词现查现判从构造上消灭此类 bug；
3. **可推导冗余**：五个候选状态全是条件的函数，FSM 为不需要记忆的东西引入记忆，再付出保持一致的持续成本；
4. **可测性**：决策链是纯函数（构造状态 → 断言行动）；FSM 需先驱动转移序列再测，脚手架成本翻倍，违背"JUnit 零后端直测"承诺。

**结构性判据（状态数量增长不改变结论）**：
> **互斥且持续的行为 → 状态机；可组合的事实 → 状态列表。**

- 状态效果（眩晕 / 流血 / 减速 / 沉默…）是**可叠加的事实**：单位可同时眩晕＋流血＋减速。FSM 同一时刻只有一个活动状态，与组合事实结构性冲突——15 类效果同时挂 5 个，需要 C(15,5) ≈ 3003 个组合状态（**状态爆炸**）；
- 状态列表模型下效果数量增长是**线性**的：`StatusType` 词表扩一项即可，查询不变（`hasControl()` 仍是一次遍历）、属性修正仍走脏标记重算；
- 控制类效果的"互斥"体现在**查询**上（存在任一控制即跳过），而非建模上。

**FSM 何时是对的（边界）**：
- 持续多 tick 的行为：引导技能（蓄力被打断有惩罚）、击退位移进行中、连招序列；
- enter / exit 副作用钩子（进入眩晕丢弃目标等）；
- Boss 阶段脚本（血量阈值切换行为模式）——此时也不该用平铺 FSM，用**分层状态机 HFSM 或行为树**（N² 转移爆炸）；
- **渲染层动画状态机**（idle ↔ walk ↔ attack ↔ death，由 CombatEvent 驱动）——表现层本来就该有，与逻辑层无状态仲裁不冲突，正是"逻辑无状态推导、表现有状态播放"的分层。

**演进路径**：出现长动作 → 决策链**顶部加一级**"存在进行中的长动作 → 推进它并跳过其余链"（与"被控制 → 跳过"同构，零重写）；Boss 专属 AI → gdx-ai 行为树（依赖已在 build，见待定清单）。原则：**普通棋子保持无状态仲裁，复杂度按需支付，不预付**。

## 四、移动：离散跳格 + 渲染插值

- 逻辑上单位**永远占据整数格**；`moveSpeed`（格/秒）= 跳格冷却的倒数（1.8 格/秒 → 每 0.556s 跳一格）
- 渲染层在两格间 lerp，逻辑零浮点路径
- **贪婪步**：4 邻格中选“使到目标曼哈顿距离最小”的**空格**；平局按固定方位优先级（上 > 下 > 左 > 右）
- **同 tick 抢格**：先遍历者先占，后来者重新评估（看到已占则改选或等待）
- **被堵死**：所有不增加距离的邻格均被占 → 本步等待（侧移绕路与 A* 在 GDD 待定清单，寻路精化后置）
- MVP 所有单位都是**接近型走位**（无风筝/拉扯），进入射程即停

## 五、攻击与弹道

### 5.1 攻击计时
- **有效攻击间隔 = 1 / (有效攻速 × 全局攻速系数)**；系数 **0.6（待调）**，`GameBalance` 新常量，敌我对称、**只在消耗点乘算**——units.json 数值与属性管线（§八两级派生）一律不动，攻速类状态（ASPD_UP 等 PCT 修正）的相对收益不变
- 计时器累积到点出手，**结转余数**（高攻速不掉次数）；攻击与移动计时器**独立累计、结转互不影响**，但同一 tick 行动互斥（出手或走步二选一——实现层口径 #3；原文"同 tick 可先后各触发一次"按实现同步作废）
- **开战蓄力（2026-09-02 修订；2026-09-09 语境更新：铺垫形式由倒计时改为清场转场，机制不变）**：开战转场「清场入阵」结束后计时器**从零开始蓄力**（修订原文"开战即就绪（无前摇概念）"）；**恒累计**语义保留——移动中、射程外照常蓄力，蓄满即可出手
- 蓄力可视化：单位头顶攻击蓄力条（attackTimer / attackInterval，蓄满即出手、出手取模归零清空重蓄）——纯表现层，见 render §5.6

### 5.2 伤害管线（普攻与技能共用，唯一管线）

```
发射/出手时：roll 暴击（仅普攻，20%，RNG 按发射序消耗）→ 冻结载荷
命中时：
  伤害 = 有效攻击力 × 技能倍率(普攻=1) × (暴击 ? 1.5 : 1)
        × 100 / (100 + 目标有效护甲)
  → 有护盾先扣盾 → 扣 HP（溢出作废）
  → 攻击者 +10 能量（命中才得）→ 受击者 +5 能量（DOT 不触发）
```

### 5.3 两类逻辑弹道（已定）

| | 锁定弹（HOMING） | 非锁定弹（LINE） |
|---|---|---|
| 目标 | 指定单位，**追踪其当前所在格** | 无目标，发射时锁定方向直线飞行 |
| 阻挡 | **不可被阻挡** | 被**路径上第一个敌方单位**挡下并命中（友军不挡，默认待确认） |
| 终结 | 到达即命中；目标已被清扫 → 落空消散（`ProjectileFizzled`，无伤害无能量） | 命中挡弹者；飞出棋盘或达射程上限消散 |
| 载荷 | 出手时冻结（伤害、暴击、技能参数） | 同左 |
| 适用 | 远程普攻、`SINGLE_TARGET` / `AOE_1` 类技能（命中点为中心爆炸） | 直线冲击类技能（STUN 状态组合，如断星锤）、未来穿透类技能 |

- 弹道**连续坐标**飞行（不占格、弹与弹无碰撞），全局速度常量 **6 格/秒**（`GameBalance`，待调；每单位覆盖字段预留不启用）
- 载荷类型由数据配置：`delivery: MELEE_INSTANT / HOMING / LINE`
- 近战与 `MELEE_INSTANT` 载体技能（HEAL/SHIELD/BUFF 类）无弹道即时结算
- 战斗结束/超时时在途弹道全部消散
- **确定性与 RNG**：弹道飞行本身零随机；暴击在发射时 roll，消耗序 = 发射序（id 序遍历内），回放可复现（RNG 消耗点清单仍只有 architecture §六登记的四类）

## 六、技能施放（V1.2：具名技能 + 组合式执行）

- **触发点**：能量跨越 100 的结算点**就地施放**（可能发生在别人攻击结算的中间）；无施法时间、无公共 CD、不清攻击计时；动画纯播报
- **技能不暴击**（暴击为普攻专属）；技能不吃攻速
- 技能是 **skills.json 中的具名资产**（units 以 `skillId` 引用，可多单位共享），定义 = **形状（shape）× 效果列表（effects ≤ 3）× 载体（delivery）**——字段终版与种子示例见 `data_schema_design.md` §五

**三步执行模型**（取代原六模板分支——数据驱动分发，代码更统一）：

```
① shape 解析目标集合（见下表）
② 载体投送（MELEE_INSTANT 即时 / HOMING 追踪 / LINE 直线——命中点触发）
③ 逐效果应用，走既有管线：
     DAMAGE       → 唯一伤害管线（有效攻击 × value × 星级倍率 × 护甲公式）
     HEAL/SHIELD  → 恢复 / 吸收（maxHp × value × 星级倍率）
     APPLY_STATUS → StatusSystem（强度与时长不随星级缩放）
```

| Shape | 目标集合 |
|-------|----------|
| `SINGLE_TARGET` | 当前锁定目标 |
| `SELF` | 施放者自身 |
| `LOWEST_ALLY` | HP% 最低友军（含自己）；全满 → 延后施放（保留能量） |
| `ALL_ALLIES` | 全体存活友军（含自己） |
| `AOE_1` | 载体落点（或当前目标格）及其 4 邻格中的所有敌人 |
| `ALL_ENEMIES` | 全体存活敌人（Boss 演出用；非 boss 引用加载期软告警） |

**旧六模板 → 组合对照**（预设概念保留，供内容设计参考）：

| 旧模板 | 组合表达 |
|--------|----------|
| NUKED 单体爆发 | `SINGLE_TARGET` + `[DAMAGE]`（HOMING） |
| AOE 范围 | `AOE_1` + `[DAMAGE]`（HOMING） |
| HEAL 治疗 | `LOWEST_ALLY` + `[HEAL]` |
| SHIELD 护盾 | `LOWEST_ALLY` + `[SHIELD]` |
| BUFF 增益 | `ALL_ALLIES` + `[APPLY_STATUS ATK_UP]` |
| STUN 眩晕 | `AOE_1` + `[APPLY_STATUS STUN]`，载体 `LINE` |

- 典型具名技能见 data_schema §五：暴走（SELF + ATK_UP/ASPD_UP 双状态）、群体治疗（ALL_ALLIES + HEAL）、超远程狙击（SINGLE_TARGET + DAMAGE 3.5）、星陨（ALL_ENEMIES，最终 Boss 演出）

## 七、异常状态系统（统一框架）

### 7.1 结构

```
ActiveStatus {
    StatusType type;      // 枚举：STUN, BLEED, SLOW, ATK_UP, ATK_DOWN, ASPD_UP, SHIELD, REGEN, ...
    float remainingTime;  // 剩余时长
    float tickTimer;      // DOT/HOT 的 1s 心跳
    float power;          // 数值（施放者快照——流血按施放当时攻击力算死，不追踪后续变化）
    int  sourceId;        // 来源（回放/调试）
}
```

### 7.2 框架规则

1. **控制类**（STUN，未来 SILENCE 等）：存在任一 → 决策链第一步跳过、能量冻结
2. **持续类**（BLEED / REGEN）：每 1s 心跳；**DOT 无视护甲（真伤）可致死**；DOT 不触发受击回能
3. **属性修改类**（ATK_UP / SLOW…）：进入第八节修正管线
4. **叠加规则**：**同 type 不叠加，刷新时长（取更长）**；不同 type 独立生效
5. 本 tick 施加的 STUN **不能取消已声明行动**（控制从下一 tick 生效）——与 H 语义一致
6. 状态随单位死亡销毁；`SHIELD` 作为特殊吸收条目同框架管理

### 7.3 三个配置入口，一个框架

技能 JSON（STUN/BUFF）、装备（龙心 = REGEN）、羁绊（兽人 6 = 开局 SHIELD）全部落到同一个 `StatusSystem`——这是 GDD synergies.json 里“结构化效果字段”的运行时落点。

## 八、属性管线：基准快照 + 战斗期修正

### 8.1 第一级：基准快照（开战一次算死）

```
UnitData.baseStats × 星级倍率(1.8 / 3.24)
  + 装备（ADD / PCT，三槽）
  + 羁绊门槛效果（ADD / PCT）
= BattleUnit 基准属性（maxHp / attack / armor / attackSpeed / moveSpeed / range）
```

**合成顺序写死：`基准 = (模板值 + ΣADD) × (1 + ΣPCT)`**（先加后乘；顺序不写死，同套装备不同结算序会得出不同数字）。

### 8.2 第二级：战斗期修正（状态变化时重算缓存）

```
有效属性 = (基准 + Σ状态ADD) × (1 + Σ状态PCT)
```

- 状态集合变化打脏标记，下一 tick 重算缓存（30 单位 × 6 属性为纳秒级）
- **百分比刻度换算**：`lifesteal / skillPower / energyGainRate` 以百分点整数存储（基准 0 / 0 / 100），结算处统一 ÷100（如 energyGainRate 115 → ×1.15 回能、lifesteal 20 → 20% 吸血）
- maxHp 被战斗期降低时 currentHp 同步钳制
- **可修改属性键白名单（9 键，与 data_schema §三 statKey 完全一致）**：`hp / attack / armor / attackSpeed / moveSpeed / range / lifesteal / energyGainRate / skillPower`——hp 的修正作用于 maxHp（currentHp 按上方钳制规则同步）；`skillPower` 在施放结算时作用于 DAMAGE/HEAL/SHIELD 幅度（与星级缩放叠乘）；JSON 的 stat 名、状态 type、代码枚举三处共用一套同名词表，杜绝字符串魔法

### 8.3 全局常量（`GameBalance`，不做每棋子配置）

暴击率 20%、暴击倍率 ×1.5、能量上限 100、命中回能 +10、受击回能 +5、DOT 心跳 1s、弹道速度 6 格/秒、索敌重评估周期 2s、跳格冷却 = 1/moveSpeed、**全局攻速系数 0.6（2026-09-02，待调）**、**开战转场时长 0.6s（2026-09-09 修订取代倒计时 3s，待调，区间 0.4~0.8；暂名 `BATTLE_INTRO_TRANSITION_SECONDS`，终名由实施计划定；`BATTLE_INTRO_GO_BEAT_SECONDS` 废弃删除）**。
