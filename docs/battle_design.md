## 二、主循环（H 语义）

```
每个逻辑 tick（60Hz，固定序）：
① 状态推进：DOT 心跳结算（可致死，直接进清扫名单）、持续时间递减、控制倒计时
② 逐单位行动（id 升序；跳过"已在清扫名单"的单位）：
     被控制（存在任一控制类状态） → 跳过
     目标失效（=已被标记死亡）   → findTarget()
     能量 ≥ 100                  → 就地施放技能（在能量过百的结算点内）
     目标在射程内（曼哈顿 ≤ range）→ 推进攻击计时器，到点发射/结算
     否则                        → 跳格冷却就绪则走一步
③ 死亡清扫：统一标记死亡、腾格（预留亡语/掉落钩子）
④ 胜负 / 超时（60s）判定
```

**关键语义**：
- **伤害立即落地**：结算点当场扣 HP，后行动者看到的是最新血量（HEAL 能奶到本 tick 刚被打残的人）
- **死亡延迟清算**：HP ≤ 0 但尚未清扫的单位在本 tick 仍是合法目标、仍可行动——互秒与“濒死反打”自然发生
- **同 tick 冲突一律由固定遍历序 + id 决胜**：确定性回放的根基

### CombatEvent 事件流

每个结算点记录纯数据事件（type / tick / sourceId / targetId / amount / 附带标志）：

| 事件 | 触发点 |
|------|--------|
| `AttackLaunched` | 近战出手 / 弹道发射（含载荷快照） |
| `Hit` | 伤害落地（含 isCrit、实际伤害、双方能量变化） |
| `Cast` | 技能施放（skillId） |
| `StatusApplied` | 状态挂载/刷新（type、时长、power） |
| `Healed` / `Shielded` | 治疗与护盾落地 |
| `UnitDied` | 死亡清扫 |
| `ProjectileFizzled` | 弹道落空/消散 |
| `BattleEnded` | 胜负/超时 |

- 事件对象建议池化复用（60Hz × 事件量的 GC 压力控制）
- 逻辑层**只产出**事件；渲染层消费事件驱动动画与飘字——逻辑/表现彻底解耦

## 三、AI：优先链决策（非行为树）

每 tick 每单位走一条固定优先链（纯函数，≤ 50 行；gdx-ai 留给未来 Boss 脚本）：

```
被控制? → 跳过
目标有效? → 无效则 findTarget()
能量满?  → 施放技能
射程内?  → 攻击
否则     → 移动一步
```

### 索引细则（findTarget）

在存活敌方（含濒死未清扫）中按优先级排序：

| 优先级 | 排序键 | 平局决胜 |
|--------|--------|----------|
| `NEAREST` | min 曼哈顿距离(自身, 敌) | id 升序 |
| `BACKLINE` | max 纵深（敌方单位到缓冲行第 3 行的距离） | 距离最近 → id |
| `LOWEST_HP` | min currentHp / maxHp | 距离 → id |
| `HIGHEST_ATK` | max 当前有效攻击力 | 距离 → id |

所有排序末位都是 **id 决胜**——确定性的最后一道保险。

### 重评估节奏（已定：非粘滞）
- **目标死亡（被清扫）→ 立即重选**
- **每 2 秒（120 tick）全局统一强制重评估**，按 id 序执行，结果可能不变
- `LOWEST_HP` / `HIGHEST_ATK` 类索敌因此会切火——已接受的已知行为

## 四、移动：离散跳格 + 渲染插值

- 逻辑上单位**永远占据整数格**；`moveSpeed`（格/秒）= 跳格冷却的倒数（1.8 格/秒 → 每 0.556s 跳一格）
- 渲染层在两格间 lerp，逻辑零浮点路径
- **贪婪步**：4 邻格中选“使到目标曼哈顿距离最小”的**空格**；平局按固定方位优先级（上 > 下 > 左 > 右）
- **同 tick 抢格**：先遍历者先占，后来者重新评估（看到已占则改选或等待）
- **被堵死**：所有不增加距离的邻格均被占 → 本步等待（侧移绕路与 A* 在 GDD 待定清单，寻路精化后置）
- MVP 所有单位都是**接近型走位**（无风筝/拉扯），进入射程即停

## 五、攻击与弹道

### 5.1 攻击计时
- `攻击间隔 = 1 / attackSpeed`；计时器累积到点出手，**结转余数**（高攻速不掉次数）
- 开战即就绪（无前摇概念）；攻击冷却与移动冷却相互独立、同 tick 可先后各触发一次

### 5.2 伤害管线（普攻与技能共用，唯一管线）

```
发射/出手时：roll 暴击（仅普攻，20%，RNG 按发射序消耗）→ 冻结载荷
命中时：
  伤害 = 有效攻击力 × 技能倍率(普攻=1) × (暴击 ? 1.5 : 1)
        × 100 / (100 + 目标有效护甲)
  → 有护盾先扣盾 → 扣 HP（溢出作废）
  → 攻击者 +10 能量（命中才得）→ 受击者 +5 能量（DOT 不触发）
```

### 5.3 两类逻辑弹道（已定）

| | 锁定弹（HOMING） | 非锁定弹（LINE） |
|---|---|---|
| 目标 | 指定单位，**追踪其当前所在格** | 无目标，发射时锁定方向直线飞行 |
| 阻挡 | **不可被阻挡** | 被**路径上第一个敌方单位**挡下并命中（友军不挡，默认待确认） |
| 终结 | 到达即命中；目标已被清扫 → 落空消散（`ProjectileFizzled`，无伤害无能量） | 命中挡弹者；飞出棋盘或达射程上限消散 |
| 载荷 | 出手时冻结（伤害、暴击、技能参数） | 同左 |
| 适用 | 远程普攻、NUKED、AOE（命中点为中心爆炸） | STUN（如断星锤直线冲击）、未来穿透类技能 |

- 弹道**连续坐标**飞行（不占格、弹与弹无碰撞），全局速度常量 **6 格/秒**（`GameBalance`，待调；每单位覆盖字段预留不启用）
- 载荷类型由数据配置：`delivery: MELEE_INSTANT / HOMING / LINE`
- 近战与 HEAL/SHIELD/BUFF 无弹道即时结算
- 战斗结束/超时时在途弹道全部消散
- **确定性与 RNG**：弹道飞行本身零随机；暴击在发射时 roll，消耗序 = 发射序（id 序遍历内），回放可复现（RNG 消耗点清单仍只有 architecture §六登记的四类）

## 六、技能施放

- **触发点**：能量跨越 100 的结算点**就地施放**（可能发生在别人攻击结算的中间）；无施法时间、无公共 CD、不清攻击计时；动画纯播报
- **技能不暴击**（暴击为普攻专属）；技能不吃攻速
- 六模板结算细则：

| 模板 | 载体 | 结算 |
|------|------|------|
| `NUKED` | HOMING | 对当前目标：有效攻击 × power × 星级倍率，走护甲公式 |
| `AOE` | HOMING | 命中点=当前目标格，爆炸命中其 **4 邻格**内所有敌人，走护甲公式 |
| `HEAL` | 即时 | 治疗 HP% 最低友军（含自己）= maxHp × power；全满则**保留能量延后** |
| `SHIELD` | 即时 | 给 HP% 最低友军吸收盾 = maxHp × power；盾先于 HP 扣、不产生能量 |
| `BUFF` | 即时 | 全体友军攻击 +power%，5s——以 `ATK_UP` 状态挂载 |
| `STUN` | LINE | 直线飞行，命中者及其 4 邻格敌人眩晕 power 秒（不能行动/回能） |

## 七、异常状态系统（统一框架）

### 7.1 结构

```
ActiveStatus {
    StatusType type;      // 枚举：STUN, BLEED, SLOW, ATK_UP, ATK_DOWN, ASPD_UP, SHIELD, REGEN, ...
    float remainingTime;  // 剩余时长
    float tickTimer;      // DOT/HOT 的 1s 心跳
    float power;          // 数值（施放者快照——流血按施放当时攻击力算死，不追踪后续变化）
    int  sourceId;        // 来源（回放/调试）
}
```

### 7.2 框架规则

1. **控制类**（STUN，未来 SILENCE 等）：存在任一 → 决策链第一步跳过、能量冻结
2. **持续类**（BLEED / REGEN）：每 1s 心跳；**DOT 无视护甲（真伤）可致死**；DOT 不触发受击回能
3. **属性修改类**（ATK_UP / SLOW…）：进入第八节修正管线
4. **叠加规则**：**同 type 不叠加，刷新时长（取更长）**；不同 type 独立生效
5. 本 tick 施加的 STUN **不能取消已声明行动**（控制从下一 tick 生效）——与 H 语义一致
6. 状态随单位死亡销毁；`SHIELD` 作为特殊吸收条目同框架管理

### 7.3 三个配置入口，一个框架

技能 JSON（STUN/BUFF）、装备（龙心 = REGEN）、羁绊（兽人 6 = 开局 SHIELD）全部落到同一个 `StatusSystem`——这是 GDD synergies.json 里“结构化效果字段”的运行时落点。

## 八、属性管线：基准快照 + 战斗期修正

### 8.1 第一级：基准快照（开战一次算死）

```
UnitData.baseStats × 星级倍率(1.8 / 3.24)
  + 装备（ADD / PCT，三槽）
  + 羁绊门槛效果（ADD / PCT）
= BattleUnit 基准属性（maxHp / attack / armor / attackSpeed / moveSpeed / range）
```

**合成顺序写死：`基准 = (模板值 + ΣADD) × (1 + ΣPCT)`**（先加后乘；顺序不写死，同套装备不同结算序会得出不同数字）。

### 8.2 第二级：战斗期修正（状态变化时重算缓存）

```
有效属性 = (基准 + Σ状态ADD) × (1 + Σ状态PCT)
```

- 状态集合变化打脏标记，下一 tick 重算缓存（30 单位 × 6 属性为纳秒级）
- maxHp 被战斗期降低时 currentHp 同步钳制
- **可修改属性键白名单**：`attack / armor / attackSpeed / moveSpeed / range / lifesteal / energyGainRate`——JSON 的 stat 名、状态 type、代码枚举三处共用一套同名词表，杜绝字符串魔法

### 8.3 全局常量（`GameBalance`，不做每棋子配置）

暴击率 20%、暴击倍率 ×1.5、能量上限 100、命中回能 +10、受击回能 +5、DOT 心跳 1s、弹道速度 6 格/秒、索敌重评估周期 2s、跳格冷却 = 1/moveSpeed。
