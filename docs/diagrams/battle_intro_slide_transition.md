# 开战转场「清场入阵」UI 提案（battle_intro_slide_transition）

> **版本**：V1.1（2026-09-09 已批准定稿；同日 **Q6 勘误**——商店栏 ⑧ 实机渲染在**底部**、战斗 HUD 在顶部，「交接同一槽位」废弃、改两屏缘各自进出，方案 A 就地适配，裁决记录见第五节。V1.0：用户看过动效分镜后逐项裁决 Q1~Q5（Q5 否决）；GDD 修订已随本次落位：`battle_design.md` V1.8 §二 / `render_design.md` V1.6 §5.6 / GDD V0.17 §6.6-§6.7；实施计划交 libgdx-impl-planner）
> **配图**：`docs/diagrams/battle_intro_slide_transition.html`（三帧分镜 + 可重播动效演示，需浏览器打开）
> **背景**：用户裁决方向——去掉开战倒计时（3-2-1 横幅），改为**备战 UI 滑出屏幕 → 展示战斗棋盘 → 开始战斗**的转场交互。本文为交互设计提案，供评判。

---

## 一、设计事实基础（来自 render §九坐标表，已实读核对）

1. **备战与战斗共用同一张棋盘**（④ 224,50,192,224，全程可见）——不存在"棋盘从别处滑入"；所谓"展示出战斗棋盘"，实际是**备战专属 UI 让位**+镜头强化。
2. **【V1.1 勘误 Q6】商店栏 ⑧ 实机渲染在底部、战斗 HUD 实机在顶部**——planner 核实：`BattleScreen.java:226` 装配从未 setPosition（整组停原点 = 底部 0..64 条带），`ShopBar.java:29` 注释「组定位 0,SHOP_BAR_Y 归 CP29 装配」从未落地，旁证 SHOP_HINT_Y 反馈记录「原 y=24 被商店卡牌遮挡」即底部；HUD 子件定位于 `BattleHud.java:43,46` 的 `VIRTUAL_H - 46`（顶部）。render §九 ⑧ 表值 `(0,296,640,64)` 与代码漂移系既有问题。V1.0 原判「共用同一顶部槽位、交接滑切」前提不成立——用户裁决**方案 A 就地适配**：两屏缘各自进出（⑧ 下滑离场 / 上滑回位，HUD 上缘外下落就位 / 上升退场），观感 = 经营层/战斗层整层交换。
3. 备战席 ② / 背包 ③ / 羁绊 ⑤ 现为"全程可见、战斗期置灰"——是否随转场滑出，是本提案的核心取舍（开放问题 Q1）。

## 二、推荐方案：「清场入阵」三帧分镜

### F0 备战期（现状不变）
全量备战 UI：顶部商店栏 + 左列（通知/背包/备战席）+ 开战按钮 + 右侧羁绊面板 + 棋盘（敌阵侦察虚影可见）+ 底部出售区/布阵提示。

### F1 转场中（点击「开战」后 ~0.6s，待调；期间逻辑冻结）
| 元素 | 动作 |
|---|---|
| 商店栏 ⑧（实机底部） | **下滑离场**（V1.1 勘误 Q6；反向转场上滑回位） |
| 战斗 HUD（实机顶部） | **自屏幕上缘外下落就位**（60s 计时条 / 变速 / 投降；BATTLE 期常驻顶部、不接管槽位——V1.1 勘误 Q6；反向上升退场） |
| 开战按钮 ⑥ + 布阵提示 + 出售区 ⑦ | 左移/淡出 |
| 备战席 ② + 背包 ③ | **左滑离场**（Q1：若判"保留置灰"则改为原地置灰） |
| 羁绊面板 ⑤ | 原地**置暗保留**（羁绊是战斗相关信息，清场不清它） |
| 通知 ⑨ / TopBar | 不动 |
| 棋盘 ④ | **镜头轻微回正**（zoom 1.06→1.0，"聚焦战场"一拍；转场期输入本就禁用，不影响命中换算） |

### F2 战斗起步（转场结束，逻辑解冻）
干净战场：棋盘成为绝对主角；双方单位攻击计时器**从零蓄力**（保留已落地的节奏三件套中的两件：计时器归零 + 头顶攻击蓄力条），蓄力条肉眼可见地填充——紧张感由"清场空拍 + 蓄力条充能"承担，首刀天然落在解冻后 1.1~2.4s。

### 节奏账（对比被废弃的倒计时案）
| | 倒计时案（废弃） | 转场案（本提案） |
|---|---|---|
| 开战到解冻 | 3s（3-2-1 大字） | **0.6s**（滑切转场，待调） |
| 紧张感来源 | 倒数仪式感 | 清场空拍 + 蓄力条充能 + 首刀延后 |
| 逻辑冻结机制 | intro 冻结（introRemaining 门控） | **同一机制复用**，仅时长改短、视觉改为滑切 |
| 零棋子局 | W2：白等 3s | **问题消失**（转场照播，无空等感） |

## 三、实施衔接预判（评审通过后由 planner 细化）

- **机制复用**：现有 `BattleState.introRemaining` 冻结门控原样保留，只把时长 3s→0.6s（新常量，待调）——逻辑层改动极小。
- **表现层**：`BattleIntroBanner`（刚落地的倒计时横幅）**退役删除**；新增转场驱动（UI 域 actor 位移/淡入出 + worldCamera zoom 回正），全部纯表现。
- **保留不动**：全局攻速系数 ×0.6、计时器从零蓄力（口径 #4 修订）、头顶攻击蓄力条——节奏三件套去一留二。
- **文档影响**：battle_design 决策 #13 修订（倒计时→转场）、render §5.6 改写、`battle_intro_countdown` 图重绘或销毁。

## 四、开放问题（请评审时逐项表态）

| # | 问题 | 提案倾向 |
|---|---|---|
| Q1 | 备战席/背包要不要随转场滑出？（滑出=战场更净；保留=失去置灰参考） | **滑出**（清场入阵的"清"字所在） |
| Q2 | 转场时长 0.6s（0.4~0.8 待调）？过短无仪式感、过长拖沓 | 0.6s 起步实测调 |
| Q3 | 战毕回备战（RESULT→SHOPPING）是否反向同款转场（商店栏下滑归位）？ | 是，同一机制反向 |
| Q4 | 棋盘镜头回正（zoom 1.06→1.0）保留吗？去掉则纯 HUD 滑切，实现更省一档 | 保留（一拍"聚焦战场"值这个钱） |
| Q5 | 替代风味：镜头**上摇**变体——备战期镜头微偏己方半场，开战时上摇展现完整战场+敌军（电影感更强，但备战期视野受限） | 不采用（侦察期看全盘是既有决策） |
