## 一、项目概述

### 1.1 核心理念
**“Roguelike 爬塔 + 自走棋摆阵 + 开箱爽感”**

这是一款单机 PVE 策略游戏。玩家扮演一位“英雄”（棋手），在奇幻场景中展开连续战斗。自走棋是核心战斗方式，Roguelike 的随机事件和“击败得宝箱”机制提供持续的刺激感。游戏旨在让玩家在 **20~30 分钟** 内体验从组建杂牌军到成型羁绊军队的爽快成长曲线。画面为统一调色板的像素风格。

### 1.2 关键爽点
- 每波敌人击败后弹出 **三选一宝箱**（装备 / 金币 / 经验）
- Boss 掉落 **传说级奖励**
- 局外解锁新英雄、新场景、新棋子池

### 1.3 差异点（对标同类）
| # | 差异 | 说明 |
|---|------|------|
| 1 | **单机 PVE 爬塔** | 无联机匹配压力，整局节奏自己掌控（vs TFT 系多人对战） |
| 2 | **失败免费原地重试** | 无生命值/出局焦虑，输只是“再试一次”（vs 传统自走棋扣血出局） |
| 3 | **纯宝箱经济** | 无利息/连胜记账，每金精打细算（vs TFT 系理财经济） |
| 4 | **25 轮短局** | 20~30 分钟一局，适合移动端碎片场景 |
| 5 | **局外英雄熟练度** | 英雄专属养成线，跨局成长（vs 单局清零） |

## 二、核心玩法循环

### 2.1 单局流程
| 阶段 | 内容 |
|------|------|
| **开局** | 从已解锁英雄中选择一位（自带被动技能），点击开始 |
| **轮次结构** | 每局 **固定 25 轮**，含 **3 个 Boss 节点（固定第 7、15、25 轮）**；第 25 轮 = 最终 Boss = 通关轮。（"20~25 轮”为后续版本局长弹性预留，当前定 25） |
| **每轮循环** | ① 侦察敌方阵型 → ② 商店购物 + 布阵调整 → ③ 自动战斗（可投降；失败原地重试，见 2.2） → ④ 宝箱三选一 |
| **放弃远征** | 暂停菜单可随时放弃本局（AbandonRun），按已达波数结算部分熟练度（每已达 1 轮 +3，见 8.1） |
| **胜利条件** | 击败第 25 轮的最终 Boss，即算“通关” |

### 2.2 战败处理（已定 1C-R：失败原地重试，取代原 1C）
- **战斗失败不会导致游戏结束，也不会推进轮次**
- 玩家停留在本轮，可继续 **购物、卖棋、调整布阵**，随时再次开战
- **敌阵在本轮内保持不变**：重试前可针对性调整站位 / 阵容，侦察因此始终有价值
- 获胜后宝箱照常发放，本轮结束时才进入下一轮
- 目的：彻底杜绝“打不过 → 软锁”死循环；25 轮 = 至少 25 场胜利（含 3 场 Boss 战），单局时长可控
- 设计说明：本规则与纯宝箱经济（第三章）互补——失败不推进，就不会出现“阵容落后 + 经济断粮”的双重死锁
- **投降（Surrender）**：战斗中可随时投降，立即判负并原地重试（避免强迫玩家看必败的 60 秒）
- **零棋子开战**：允许（StartBattle 无前置校验）；零棋子战败**无宝箱收益、且不计入怜悯连败计数**（防刷规则见 3.2）

## 三、经济与商店系统（已定：纯宝箱经济）

### 3.1 总原则
- **没有每轮固定工资、没有利息、没有连胜奖**——金币几乎全部来自宝箱与卖棋子
- 金币极度稀缺 → “买棋子 / 刷商店 / 买经验”三方竞争，每一金都要精打细算

### 3.2 收入来源
| 来源 | 规则 | 备注 |
|------|------|------|
| **起始金币** | 开局 10 金 | 数值待调 |
| **宝箱（主要来源）** | 三选一中常驻 1 个金币选项，数值 = **3 + floor(轮次 / 3)** 金（锚点：第 1 轮 3 金、第 6 轮 5 金、第 12 轮 7 金、第 21 轮起 10 金封顶）；Boss 箱（第 7/15/25 轮）为 **2 倍** | 增长律为线性台阶，待调 |
| **卖棋子** | 见 3.6 | 唯一的“随时可变现”来源 |
| **怜悯金币（保底）** | 本轮连续失败第 3 次起，每次再败 +1 金；**每轮至多 +3**；**零棋子战败不计入连败计数**（防“空场秒投降刷保底”） | 防极端死局的最后阀门，数值待调 |

### 3.3 支出
| 用途 | 价格 |
|------|------|
| 购买棋子 | 按费阶 1 / 2 / 3 金 |
| 商店刷新 | 2 金（整批替换 5 个槽位） |
| 购买经验 | 4 金 = 4 经验 |

### 3.4 商店规则
- 槽位 **5 个**；棋子按费阶随轮次逐步解锁（1 费全期 / 2 费约第 4 轮起 / 3 费约第 8 轮起，待调）
- **每轮开始免费自动刷新一次**（新轮进入备战时触发，属系统行为；重试回备战不触发；轮内主动刷新才消耗 2 金）
- **费阶概率表**（锚点值，逐轮线性插值，待调；基于 24 棋子池 1 费 10 / 2 费 9 / 3 费 5）：

| 轮次 | 1 费 | 2 费 | 3 费 |
|------|------|------|------|
| 1~3 | 100% | — | — |
| 5 | 70% | 30% | — |
| 10 | 50% | 40% | 10% |
| 15 | 40% | 45% | 15% |
| 21+ | 35% | 45% | 20% |

- MVP **不做商店锁定**功能（列入待定，后续按需补）

### 3.5 棋手等级与人口（已定：等级决定人口，上限 9）
经验来源 = 花金币购买（4 金 = 4 经验）+ 宝箱中的“经验书”选项。**无免费自动经验**（与纯宝箱哲学一致）。

| 棋手等级 | 人口上限 | 升级所需经验 |
|----------|----------|--------------|
| Lv.1 | 3 | 4 |
| Lv.2 | 4 | 8 |
| Lv.3 | 5 | 16 |
| Lv.4 | 6 | 24 |
| Lv.5 | 7 | 40 |
| Lv.6 | 8 | 56 |
| Lv.7 | 9 | ——（封顶） |

### 3.6 卖出规则
- 卖出返还 **累计花费的 100%**（升星棋子按合成所耗 3 份成本合计返还）
- 卖出时已装备的装备**自动卸下回背包**（与 B2 可拆卸哲学一致，不随棋子消失）
- 与 B2 同一哲学：降低决策压力，鼓励大胆试错；配合 2 金刷新费形成软性摩擦，防止无限刷
- 数值待调（若出现滥用可下调为 90%）

## 四、棋盘与棋子

### 4.1 棋盘布局（已定：6 列 × 7 行，共享棋盘）
- **网格大小**：**6 列 × 7 行**（备选 7×8，若后期测试走位空间不足再评估切换）
- **一块共享棋盘**，敌我同场：
  - 第 0~2 行：敌方布阵区
  - 第 3 行：空白缓冲带（开战时无人，供双方推进）
  - 第 4~6 行：玩家布阵区（18 格）
- **关键区分**：棋盘网格 ≠ 可上场棋子数
- **人口上限**：初始可上阵 3 个，最高 **9 个**（Lv.7，见 3.5）
- 空余网格用于棋子战斗时的移动和走位
- **备战席**：9 格，位于棋盘侧边（UI 布局待定，见 §11，本章不载）

### 4.2 棋子池规模（已定：MVP 共 24 个）
- **24 个棋子 = 1 费 10 / 2 费 9 / 3 费 5**，覆盖 6 个首发羁绊（见 5.1）
- 亡灵、巨人阵营棋子随**场景解锁**（墓穴 / 雪山）后进入商店池
- 逐个棋子的数值表见 §11 待定（本条只锁规模）

### 4.3 升星规则（3 合 1）
- **三个同名同星棋子自动合成高一星**（商店买到第三个时立即触发）
- 属性 = 基础值 × `upgradeMultiplier ^ (星级 - 1)`，即 2 星 ×1.8、3 星 ×3.24
- 技能倍率随星级成长：×(1 + 0.5 × (星级 - 1))，即 2 星 ×1.5、3 星 ×2.0
- **星级上限为 3 星**；3 星棋子不再参与合成（防止未来新增获取途径时越界）

## 五、羁绊与装备系统

### 5.1 羁绊系统（已定 A3：混合门槛）
采用 **2/4/6** 或 **3/5/7** 的分级门槛。

**门槛终态**：现有内容统一采用 **2/4/6**；`thresholds` 数组天然支持 3/5/7，个别羁绊可按设计需要在配置中自选。

**MVP 首发羁绊 6 个**：兽人 / 战士 / 法师 / 刺客 / 野兽 / 游侠；**亡灵、巨人随场景解锁开放**（与背景文档阵营设定一致）。首发羁绊 (2) 档数值草案（待调）：

| 羁绊 | (2) 档效果 |
|------|------------|
| 兽人 | 全体友军生命值 +150 |
| 战士 | 全体友军护甲 +20 |
| 法师 | 全体友军技能倍率 +15% |
| 刺客 | 全体友军攻击力 +20% |
| 野兽 | 全体友军攻击速度 +15% |
| 游侠 | 全体友军攻击距离 +1 |

| 门槛 | 效果示例（以“兽人”为例） |
|------|---------------------------|
| (2) 兽人 | 全体友军生命值 +150 |
| (4) 兽人 | 全体友军生命值 +400，攻击力 +20% |
| (6) 兽人 | 全体友军开局获得 30% 最大生命值的护盾 |

- 策略分支：极致纯种（6 个同羁绊）或均衡混搭（4+4）
- **双通道计数**：种族与职业各自独立计数（如“兽人战士”同时计入兽人羁绊与战士羁绊）

### 5.2 装备系统（已定 B2：灵活可拆卸）
- **装备是背包物品**，可随时从棋子 A 卸下装到棋子 B
- 每个棋子限穿 **3 件**：武器 + 盔甲 + 饰品
- 装备掉落来源：宝箱（普通 / Boss）
- 意义：降低决策压力，鼓励大胆尝试
- 装备**不与技能联动**（见 6.5 简易技能定义）
- **MVP 无合成**：宝箱直接产出成品装备；“白装合成成装”留作大版本扩展（若引入则新增 `CombineEquipment` 命令）

**三槽属性池**：武器 → 攻击力 / 攻击速度；盔甲 → 护甲 / 生命值；饰品 → 特殊效果（能量获取 / 移速 / 吸血等）

**示例装备（最小可验收集，数值待调）**：

| 装备 | 槽位 | 稀有度 | 效果 |
|------|------|--------|------|
| 铁剑 | 武器 | 白 | 攻击力 +20% |
| 秘银胸甲 | 盔甲 | 白 | 护甲 +20 |
| 战歌号角 | 饰品 | 成 | 全体友军能量获取 +15% |
| 龙心 | 盔甲 | 传说 | 生命 +400，每 5 秒回复 2% 最大生命 |

**宝箱掉落权重骨架（待调）**：三选一各选项独立生成；装备选项的稀有度分布为 白 70% / 成 25% / 传 5%；Boss 箱必含 ≥1 成装及以上，传说概率大幅提升。

## 六、战斗系统

### 6.1 攻击优先级（已定：方案 A + 特化）
**默认规则**：
- 所有棋子遵循 **“攻击最近敌方单位”** 原则（曼哈顿距离）

**特化机制**：
- 部分棋子可通过配置覆盖默认规则，支持以下优先级类型：
  - `BACKLINE`：优先攻击最后排（刺客）
  - `LOWEST_HP`：优先攻击血量百分比最低者
  - `HIGHEST_ATK`：优先攻击攻击力最高者
- 特化通过数据表 `specialPriority` 字段配置，代码中统一在 `findTarget()` 方法判断
- **目标重选**：目标死亡（被清扫）后立即重选；此外**每 2 秒全局统一强制重评估**（按 id 序，结果可能不变；`LOWEST_HP` 类索敌会切火——已知行为）

### 6.2 伤害计算公式（已定：方案 1 - 百分比减伤）
```
实际伤害 = 攻击力 × (100 / (100 + 护甲))
```
- 护甲提供百分比减伤，收益递减，永不完全免疫
- 适合 25 轮的数值成长曲线

**暴击（已定：随机暴击）**：
- 普攻有 **20%** 概率暴击，造成 **×1.5** 伤害（数值待调）
- 暴击在**发射/出手时判定**并冻结进弹道载荷，经 `RandomGenerator` 按固定发射序消耗随机数——确定性回放不受影响（见 `architecture_design.md` §六、`battle_design.md` §五）

### 6.3 攻击范围与移动
- `range` 以格为单位，**曼哈顿距离 ≤ range** 视为可攻击（近战 1，远程默认 **3**；个别远程 4，随数值表落定，待调）
- 每个棋子有 `moveSpeed`（格/秒）属性：近战约 1.0、远程约 0.8、刺客约 1.8（待调）
- 移动为 **4 向（上下左右）逐格推进**，与索敌所用的曼哈顿距离口径一致
- 战斗为**实时**（`attackSpeed` 次/秒）；一格同时最多 1 个棋子，移动路径被挡时绕行（MVP 先做直线路径 + 简单绕行，寻路精化列入待定）
- **弹道（远程普攻与部分技能，逻辑弹道非纯视觉）**：两类——**锁定弹**（HOMING：指定目标、追踪其当前位置、不可被阻挡，目标死亡则落空）与**非锁定弹**（LINE：发射时定向直线飞行、被路径上第一个敌方单位挡下）；全局弹道速度 6 格/秒（待调）。近战与治疗/增益类即时结算。详见 `battle_design.md` §五

### 6.4 战斗超时
- 单场战斗限时 **60 秒**（待调），超时未分胜负判玩家失败（等同战败，原地重试）
- 目的：防止双高护甲阵容僵局拖死节奏

### 6.5 能量与简易技能（已定：每个棋子 1 个主动技能）
- **能量系统**：初始 0，上限 100；普攻**命中** +10（攻击者，落空不得）；被直伤命中 +5（受击者；DOT 不触发）；满 100 **自动施放**技能并清零；眩晕时暂停积攒
- 技能类型 MVP 限定 6 类模板：

| 类型 | 效果模板 | 示例 |
|------|----------|------|
| `NUKED` 单体爆发 | 对当前目标造成 攻击力 × power 伤害 | 火球 |
| `AOE` 范围 | 对目标及其周围 1 格造成 攻击力 × power 伤害 | 顺劈 |
| `HEAL` 治疗 | 治疗血量百分比最低友军 maxHp × power | 圣光 |
| `SHIELD` 护盾 | 为血量最低友军添加 maxHp × power 护盾 | 圣盾 |
| `BUFF` 增益 | 全体友军攻击力 +power%，持续 5 秒 | 战吼 |
| `STUN` 眩晕 | 眩晕目标及其相邻格 power 秒 | 重锤 |

- 技能伤害/数值均以“攻击力 / 最大生命值”为基数 × 倍率，**不引入独立法术强度**，不与装备联动
- 无目标可选时（如 HEAL 全队满血）延后施放，能量保留

### 6.6 战斗流程
1. 每个棋子执行 `findTarget()` 锁定目标
2. 若目标在攻击范围内 → 发起攻击：近战即时结算；远程发射**弹道**（命中时结算伤害与双方能量，暴击在发射时已判定）；否则 → 以 `moveSpeed` 4 向逐格向目标移动
3. 能量满 100 → 自动施放技能（攻击动画 + 闪光特效）
4. 伤害数字浮动反馈（普攻 / 暴击 / 技能 / 治疗分色）
5. 一方全灭或超时 → 结算（胜 → 宝箱；败 → 原地重试）

## 七、关卡与波次设计

### 7.1 轮次结构（已定 1B：固定 25 轮）
| 阶段 | 轮次 | 敌人强度 | 设计目标 |
|------|------|----------|----------|
| 新手期 | 1~5 | 1~3 个棋子，无羁绊 | 熟悉操作，积累经济 |
| 成长期 | 6~12 | 初级羁绊（如 2 战士） | 引导玩家规划阵容 |
| 成型期 | 13~19 | 中级羁绊（如 4 法师），少量装备 | 检验阵容合理性 |
| 决战期 | 20~25 | 高级羁绊（如 6 战士），传说装备 | 终极考验（第 25 轮 = 最终 Boss） |

### 7.2 Boss 节点
- 固定出现在第 **7、15、25** 轮；**第 25 轮即最终 Boss / 通关轮**
- 属性倍率基准（定值）：**普通 Boss HP ×2.5、攻击 ×2.0；最终 Boss HP ×3.0、攻击 ×2.5**（个体属性表随棋子总表落定）
- 专属技能选自 6 类模板的加强版配置：

| 场景 | Boss | 轮次 | 专属技能 | 加强方向 |
|------|------|------|----------|----------|
| 森林 | 荆棘之母 | 7 | AOE 荆棘藤蔓 | HP ×2.5 |
| 森林 | 独眼猎神 | 15 | NUKED 穿云箭 | 攻击 ×2.0 |

### 7.3 敌人生成逻辑（已定 2B：半随机池）
- **强度系数**：`k = 1 + 0.1 × (轮次 − 1)`（待调）；**敌方棋子数值 = 模板基础值 × k**
  - 锚点算例：第 5 轮 k = 1.4，1 费模板生命 100 → 140；第 25 轮 k = 3.4
- **敌方上场人数**（锚点，逐轮线性插值，待调）：第 1 轮 1 人、第 3 轮 2 人、第 5 轮 3 人、第 8 轮 4 人、第 12 轮 5 人、第 16 轮 6 人、第 20 轮 7 人、第 25 轮 8 人
- 从当前场景的 **敌人池** 中随机抽取棋子模板，按预设阵型模板（前排肉 + 后排输出）自动布阵
- 每次开局敌人组合不同，**确保重玩性**
- **重试稳定性**：同一轮内多次重试，敌阵保持不变（配合 2.2，让玩家能针对性反制）

| 墓穴 | 通关森林 | 亡灵 + 法师（吸血 / 减抗） | 死亡骑士 |

## 八、局外成长系统（已定 3B：英雄经验解锁）

### 8.1 英雄熟练度机制
- 每使用某个英雄通关（或达到特定波数），该英雄获得 **熟练度经验**
- **熟练度三件套**（待调）：等级上限 **Lv.5**；每级所需经验 **50 / 100 / 150 / 200**（Lv.1→2 起）；获取：**通关 +60、每通过 1 轮 +3**
- **AbandonRun 折算**：每已达 1 轮 +3 熟练度（与每轮获取口径一致）
- 熟练度升级后，**永久解锁该英雄专属加成**：

| 等级 | 解锁内容 |
|------|----------|
| Lv.1 | 初始金币 +2 |
| Lv.2 | 商店稀有棋子概率 +5%（仅该英雄） |
| Lv.3 | 解锁该英雄专属传奇棋子（仅该英雄可用） |
| ... | 更多待设计 |

**首发英雄被动草案**（量级锚点，待调；完整数值见 §11）：

| 英雄 | 被动 |
|------|------|

| 灰烬诗人奥兰多 | 「战歌」全队能量获取 +15% |

### 8.2 全局解锁
- 使用**任意英雄**首次通关“森林”→ 解锁“墓穴”
- 新场景包含：全新敌人池 + 专属棋子 + 新 Boss

## 九、美术与音效方向（已定：32px / 640×360）

### 9.1 基础规格
| 项目 | 规格 |
|------|------|
| 虚拟分辨率 | **640 × 360**（16:9） |
| 格子 | **32 × 32 px**（棋盘整体 192 × 224 px） |

### 9.2 Viewport 与多端适配
- 使用 `FitViewport(640, 360)`：等比缩放、多余部分黑边，杜绝拉伸变形
- PC（lwjgl3）默认窗口 1280 × 720（整数 2 倍缩放，像素绝对干净）
- Android 强制横屏；输入坐标必须经 `viewport.unproject()` 换算（详见 `user_input_design.md` 陷阱表）

### 9.3 动画帧数（MVP 精简标准）
| 动作 | 帧数 | 说明 |
|------|------|------|
| 待机 idle | 2 | 呼吸感即可 |
| 移动 walk | 2 | 可复用待机帧 + 位移 |
| 攻击 attack | 3 | 前摇 / 命中 / 收招 |
| 施法 cast | 2 | 可复用攻击帧 + 技能闪光 |
| 死亡 death | 3 | 或用缩放淡出替代 |

- 伤害飘字使用像素数字字模；普攻 / 暴击 / 技能伤害 / 治疗用不同颜色区分（暴击机制见 6.2）

### 9.4 像素字体（中文）
- 中文像素字体稀缺，推荐开源 CJK 像素字体：**Zpix** 或 **Fusion Pixel Font**
- 若字体渲染效果不佳，UI 正文可退回普通矢量字体 + 像素风 UI 边框，保持整体协调

### 9.5 音效（MVP 最小集）
- 关键音效：攻击命中 / 技能施放 / 胜利 / 失败 / 开箱 / 购买
- BGM：每场景 1 首（选型待定）
- **文件格式**：音效 **WAV**、BGM **OGG**（双端兼容）

## 十、技术架构（LibGDX）

### 10.1 技术选型与包结构
**Why LibGDX**：① 主战语言 Java，生态与工具链熟悉；② 纯单机 2D 像素游戏无需重型引擎与编辑器；③ PC（LWJGL3）与 Android 一套代码；④ 开源免费、无运行时分成；⑤ 像素渲染控制直接（Viewport / Camera / 整数缩放可控）。

包结构对齐实际项目 `com.voidvvv.kz_auto_chess_n`，全部位于 core 模块：

```
core/src/main/java/com/voidvvv/kz_auto_chess_n/
├── Main.java               # ApplicationAdapter 入口
├── screens/                # Screen 实现（BattleScreen / HeroSelectScreen 等）
├── entities/               # 运行时对象
│   ├── Unit.java           # 名单实体（准不变）
│   ├── BattleUnit.java     # 战斗实例（开战派生，用后即弃）
│   └── Player.java
├── data/                   # 静态模板（纯数据，从 JSON 加载）
│   ├── UnitData.java
│   ├── SkillData.java
│   ├── SynergyData.java
│   └── EquipmentData.java
├── config/                 # JSON 加载器
├── command/                # GameCommand / CommandManager（对接 user_input_design.md）
├── systems/                # 核心系统
│   ├── BattleSystem.java
│   ├── SynergySystem.java
│   ├── WaveGenerator.java
│   └── ShopSystem.java
└── utils/
```

> **架构对齐说明**：`user_input_design.md` 中 `RunContext`（V1.3 前原名 `BattleContext`）的确定性设计保留，价值定位为 **录像回放 / 单元测试 / 存档**（本项目为纯单机）。
