## 现状盘点与痛点分析

### 痛点核实："AI 生成感"从哪来

现状：8 条羁绊 `syn_orc / syn_warrior / syn_mage / syn_assassin / syn_beast / syn_ranger / syn_undead / syn_giant`（GDD §5.1 记 6 条；亡灵/巨人已入 `assets/data/synergies.json:61-81`，**文档滞后于数据**），统一 2/4/6 档位替换制。三条结构性证据：

1. **表达形态单一**：全部档位效果走 stat 通道（9 键数值修正，data_schema §六）；唯一非 stat 特例是兽人(6) 的开局 SHIELD——而 effect 通道代码只认 SHIELD 一种，遇到其他直接抛错（`BattleSystem.java:294-297`）。
2. **同质化**：8 条里 7 条含攻击/攻速加成、4 条堆 HP/护甲——羁绊之间的区别是"数值侧重不同"，不是"打法不同"。
3. **零克制**：任何两条羁绊之间不存在"谁怕谁"；全项目唯一的克制表达是索敌特化（刺客 BACKLINE 切后排，GDD §6.1）。

伤害的体验：羁绊是自走棋的构筑目标与核心爽点（GDD §1.1 "成型羁绊军队的爽快成长曲线"）——现在凑羁绊只改数字不改打法，构筑决策退化成"挑数值大的"。

根因：**容器先于内容定稿**。Phase 1 数据层先行，羁绊 schema 本身只装得下 `{stat, op, value}` 三元组——不是数值选得不好，是容器只有这么大。所以"从头设计羁绊"必然连"容器"（钩子层/效果通道）一起讨论——你把"机制/钩子"和"羁绊"放在同一句话里提，直觉是对的。

### 棋子池现状（重设计的真实起点）

- GDD §4.2 承诺 24 子（1费10/2费9/3费5），`assets/data/units.json` 实际 **18 个非 Boss 单位**（1费6/2费5/3费7）——承诺池从未完整落地。重设计是"18→24 补量 + 全员重排"的窗口，比"改 24 个存量"自由。
- 实际分布：种族 兽人2 / 野兽3 / 暗夜3 / 精灵3 / 亡灵3 / 巨人3 / 人类1（暗夜/精灵/人类 = 风味，不计羁绊，data_schema §六）；职业 战士7 / 法师4 / 刺客4 / 游侠3。
- **死内容警告**：人口上限 9（GDD §3.5）+ 当前分布下，除战士（7 个）外没有任何羁绊凑得齐 6 档——高档效果实际全部不可达。

## 我的反馈

**赞同**：
- **从头共创羁绊，方向成立且必要。**"零参与"不是感觉问题而是结构问题：8 条羁绊没有任何一条改变"怎么打"，而自走棋的质变爽点恰恰来自"凑齐 6 刺客全场跳后排"这种规则改变。这一层 AI 补不了——它需要你先决定"这游戏里几种打法幻想互相对抗"。
- **你给的顺序（机制 → 钩子 → 羁绊 → 技能）在结构上是对的。**羁绊特色和棋子个性都要用"机制词汇"说话；词汇表和挂点不定，羁绊讨论会退化成数值讨论——现状就是前车之鉴。

**担忧**（只提示，决策权在你）：
- **钩子层是基建，最大风险是"一次做全"。** 全生命周期十几个挂点一次铺完，工作量与回归测试面都大。倾向按 D1 选中的机制倒推挂点、只修被选中的路（见 D3）。
- **确定性回放是红线。** 现状战斗随机仅暴击一项（GDD 决策日志 2026-08-20 / architecture §六）。新机制凡带概率（格挡、触发几率），每个都是新 RNG 消耗点，必须登记 architecture §六清单，否则同 seed 对拍会碎。
- **慢速化环境对"拖"型机制不友好。** ×0.6 全局攻速已把战斗拉长 1.4~1.7 倍（GDD §6.7 观察点），60s 超时判玩家负（GDD §6.4）。高回复/高护甲反击流一旦成型，最可能撞超时判负——设计 archetype 时留意"净输出速率下限"。
- **机制的同义词风险：** 同一机制可以进棋子、装备、羁绊三处（吸血现状就是三处重复：兽人(6)/战士(6)/亡灵全系 + baseStats.lifesteal + 饰品池，GDD §5.1/§5.2）。共创时要定"谁负责什么"的分工，避免羁绊沦为棋子机制的放大粘贴。

**与现有设计/裁决的撞点**（只列出）：
- **LINE 弹道"本期不做"是 Q2 既定裁决**（`SkillExecutor.java:50-52` 遇 LINE 直接抛异常；`Projectile.java` HOMING 唯一形态）。可挡弹道依赖它——D2 已拍板（2026-11-16）拦截层**要做**（只拦不弹）；LINE 复用 vs 新拦截层的取舍归 libgdx-impl-planner。
- **"每棋子 1 个主动技能、能量满自动施放"是已定决策**（GDD 决策日志 2026-08-19）。技能扩展若加被动位/触发位，是"增槽"不是"改规则"，但口径需明示（D9）。
- **GDD §5.1 只记 6 羁绊，assets 已有 8**——以 assets 为现状基线；GDD 成文时由 gdd-writer 补记。
- **敌方同样结算羁绊**（`BattleSystem.java:90-91,119-120`：敌方侧 resolve + 开局效果落地）——GDD §7.3 只规定敌方人数与强度系数，敌方羁绊构成现靠场景池随机自然形成。羁绊越强敌人越强，重设计时敌方池要按羁绊主题同步重排（D10）。
- **光环/格子机制已有前稿**（battle_zone_pieces.md 路线 A/B/C，待拍板）——本文把它当"词汇表里已占位的一行"，具体路线回前稿讨论，避免两线并行打架。

## 方案构想：四份底图 + 一份议程

> 本部分是**组织知识与选项空间**：盘点"有什么、缺什么、可以怎么组织"。所有"应当是什么"留白给议程。

### 一、棋子机制分类学（词汇表，供 D1 勾选）

**怎么读**：机制 = 乐高块；棋子（baseStats/技能）、羁绊、装备、场景都是用块拼的载体。现状三档——**已有**＝引擎现在就支持；**部分**＝有雏形需扩展；**缺失**＝需新钩子或新系统（对应 §二）。

**A. 输出向**

| 机制 | 一句话定义 | 设计价值（它制造什么） | 现状与锚点 |
|---|---|---|---|
| 吸血 | 造成伤害按比例回自身 | 续航与输出绑定；近战群狼核心 | **已有**：LIFESTEAL 键；仅普攻直伤触发、技能不吸（`DamagePipeline.java:46-48`） |
| 暴击 | 概率放大单次伤害 | 赌性与期望管理 | **已有**：全局常量 20%/×1.5（battle §8.3），非棋子个性。**D1 勾选 = 口径升级**（2026-11-16）：升格为棋子级词汇——暴击率/暴击伤害属性化，登记为**口径变化**而非新增机制 |
| 攻击附带状态 | 普攻命中附毒/减速等 | 输出转功能，粘住目标 | **部分**：APPLY_STATUS 词汇已有但只挂技能；普攻无附带通道 |
| 穿甲 | 削减/无视目标护甲 | 对高甲的第一块克制键（克巨人/战士） | **缺失**：伤害公式单一护甲项（battle §5.2） |
| 真伤直击 | 直伤无视护甲 | 甲盾流的极端答案 | **部分**：DOT 已走真伤（`StatusSystem.java:104-105`）；直伤形态无 |
| 斩杀/处决 | 对低血目标增伤 | 收割节奏；与 LOWEST_HP 索敌咬合 | **缺失** |
| 放逐（处决系·暂名，D1 新造 2026-11-16） | 满足条件直接**移除**一个敌人，**不触发亡语** | 与斩杀构成处决系两档（增伤收割 vs 直接移除）；"不触发亡语"是本项目第一条明确设计的克制关系（克亡语/不死流） | **缺失**；钩子依赖：需**独立于伤害管线的移除路径**——若走死亡清扫（battle §二④）必然触发亡语位，二者必须分流 |
| 连击/多段 | 一次出手多次结算 | 与攻速正交的第二输出轴 | **缺失** |

**B. 生存向**

| 机制 | 一句话定义 | 设计价值 | 现状与锚点 |
|---|---|---|---|
| 免伤% | 受到伤害按比例直接减少 | 与护甲正交的第二减伤轴（还能克真伤） | **部分**：护甲减伤 + SHIELD 已有；乘算免伤% 缺失——管线无受击前窗口 |
| 护盾 | 先扣盾后扣血 | 可量化的临时生存；对轰节奏 | **已有**：SHIELD（开局/技能/状态三入口） |
| 再生 | 周期回血 | 不依赖输出的拖延轴 | **已有**：REGEN（装备入口） |
| 反弹伤害（荆棘） | 被命中时反伤攻击者 | "打不打他"成为决策；克刺客贴脸 | **缺失**：受击后无挂点 |
| 闪避 | 概率完全免疫一次攻击 | 波动型生存 | **缺失**；新 RNG 消耗点须登记（architecture §六）。注：原与"格挡"同行——2026-11-16 裁决格挡形态 = **挡掉敌方投射物**，与 D 表「格挡弹道」并为同一机制（见该行）；泛化"概率减伤格挡"日后若要做再另登记 |
| 不死/复活 | 致死后复活或保留 | 亡灵幻想标配；拖延质变 | **缺失**：死亡即清扫（battle §二④） |
| 亡语 | 死亡瞬间触发效果 | 反收割，"换掉我更亏" | **缺失**：清扫预留位（battle §九；`BattleSystem.java:160-172` 现无） |

| 受击时/后 | 被打瞬间 / 之后 | **缺失**（回能 + 吸血是两处硬编码雏形） |
| 施法前/后 | 技能施放前后 | **缺失**（CAST 事件在效果前发，`SkillExecutor.java:67`） |
| 击杀后 | 击杀瞬间 | **缺失**（UNIT_DIED 无击杀者归因，`CombatEvent.java:79-81`） |
| 死亡时 | 死亡清扫瞬间 | **缺失**（battle §九预留位） |
| 周期 | 每隔 N 秒 | **部分**：DOT/REGEN 1s 心跳；装备被动可自定义间隔（`StatusSystem.java:41`） |
| 条件 | 血量阈值/人数差等 | **缺失** |

**小结**：现状覆盖 = 输出数值与数值型生存丰富、**触发类与空间克制类几乎空白**——这与羁绊 archetype 的空白（§三）互为因果：词汇表缺的词，羁绊也写不出来。

### 二、战斗事件钩子层（配图：`../diagrams/battle_hook_points.md`）

**概念澄清（先分清两个东西）**：
- **CombatEvent 事件流**（battle §二，9 类：`CombatEvent.java:16-19`）= **事后事实记录**——逻辑层只写不读，消费者是渲染动画/飘字/战斗日志/回放对拍。它**不是**钩子系统。
- 你说的"**监听**" = 逻辑结算管线里的**生效插入点**。现状全部硬编码（吸血、受击回能两处），没有可配置挂载。
- 落地形态两选（讨论点 D3）：**管线内挂点**（结算函数留触发位，如 DamagePipeline 内）或**逻辑内事件分发**（逻辑层消费自己的事件副本）。【我的倾向：管线内挂点——顺序确定性可控、少一层间接、与现有"结算序每步可观察"的写法一致；供参考】

**每羁绊"户口本"（共创时每条羁绊填一张）**：
1. **身份幻想**：一句话，玩家为什么想要它（lore §四 有 8 条现成底稿可改写）

- **C 矩阵特化格**：种族×职业交点 = 专属机制（"兽人法师=唯一火法"）——个性最强、内容量爆炸

### 四、技能扩展性（"以后也能扩展"的底图）

**现有模型能表达什么**：主动、能量驱动、瞬发或弹道投送的 伤害/治疗/护盾/挂状态 组合——shape 7 × effects 4 类 ≤3 × delivery 3（data_schema §五；battle §六；LINE 未实现 `SkillExecutor.java:50-52`）。

**表达不了什么**（对照 §一 的机制表）：

| 缺口 | 例子 | 为什么表达不了 |
|---|---|---|
| 被动技能 | 常驻荆棘的龟 | units.json 只有 skillId 一个槽；棋子级被动只能借装备 passiveStatus 通道的思路 |
| 触发式技能 | 击杀后重置能量 | 无触发维度字段；技能只在能量满时施放（GDD §6.5） |
| 条件效果 | 目标 <30% 血增伤 | effects 无条件谓词，value 是常数 |
| 多段/延迟 | 3 秒后二段爆炸 | effects 依次立即应用，无时序字段 |
| 引导/蓄力 | 读条大招 | 无施法时间概念（battle §六）；长动作已登记为 FSM 边界（battle §三） |
| 召唤 | 召狼作战 | 无生成单位的 effect 类型（机制本批搁置、日后专题，2026-11-16） |
| 光环 | — | 前稿路线 A/B/C 待拍板，不在本文重复 |

**扩展方向选项**：
1. **扩效果词表**：SkillEffectType 加 Delay 等——延续组合哲学；但"触发/条件"塞进 effect 里表达别扭（Summon 类随召唤本批搁置、优先级下调，2026-11-16）
2. **新增被动槽**：units.json 加 passives[]（常驻 stat/状态/光环引用）——纯数据层，不依赖钩子层的部分可先行
3. **触发式技能**：trigger → 内嵌效果 的映射（ON_ATTACK / ON_KILL / ON_DEATH / ON_HIT…），复用 SkillExecutor 三步执行——与 §二钩子点一一对应
4. **通用钩子订阅式**：技能声明订阅任意事件点——最泛化也最重，MVP 不建议
- 【我的倾向：**2+3 组合**——被动槽吃"常驻类"机制、触发映射吃"时机类"机制，合起来覆盖 §一 缺失项的大多数；且都不动"每子 1 主动技能"的已定决策（决策日志 2026-08-19），是增槽不是改规则；供参考】
