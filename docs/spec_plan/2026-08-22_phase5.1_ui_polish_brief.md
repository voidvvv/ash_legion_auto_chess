## 2. 需求明细

### R1. 悬停预览（先查看再决策）
- **棋盘域**（棋盘 6×7 与备战席 3×3 的棋子）：鼠标悬停 ~250ms 出只读预览卡。现状：`BoardInputProcessor` 只有按下/拖拽/松手三态与 `unitClickListener` 死区点击回调，无 mouseMoved 悬停轨迹——需新增悬停状态机（含与拖拽、`modalBlocked`、非 SHOPPING 期的互斥抑制）。
- **商店卡**（`ShopBar` 5 卡，Scene2D）：悬停显示**模板级**预览（名/费阶/属性/技能/羁绊）——玩家可先查看再购买。
- 预览内容为模板数据（UnitData 级），不含 spend/已穿装备等实例状态；与 UnitDetailDialog 共用同一套文案格式化函数（建议抽纯函数，headless 可测）。
- 锚点：固定卡位（具体坐标 planner 按 BoardGeometry 现状定，需说明防遮挡理由——候选：棋盘左 128~224 空带 / 顶部 hint 带等）。

### R2. 棋子详情补全（弹窗信息架构重排）
- **技能描述**：`skills.json` 已有 `name` + `desc` 字段（如 "战吼——号令全军，攻击提升"），显示层缺失。planner 核对 SkillData 是否已解析 desc，缺则补 accessor。显示于详情弹窗与悬停卡。
- **羁绊描述**：`synergies.json` 现无 desc（裁决：加字段）。建议口径（planner 拟定最终版）：synergy 级 `desc` 一句主题描述（手写）+ 档位数值行仍由 thresholds/effects 结构化数据生成（如 "2：生命+150；4：生命+400·攻击+20%"），两全其美。显示棋子的两条羁绊（种族+职业）。
- **全中文属性标签**（与 R3 联动）：HP/ATK/ARMOR/ASPD/RANGE/MSPD/spend → 生命/攻击/护甲/攻速/射程/移速/累计花费（术语表见 R3）。
- #2 布局修复（42d9104）为新基线，本次信息架构在其上重排（内容行数增加，弹窗尺寸/分区由 planner 定）。

### R3. 全 UI 中文化
英文出没点（已核实部分，planner 全量 grep 复核补全）：
- `RunState.notices` 动态行：systems（ShopSystem/RunFlowSystem/RosterSystem/EquipmentSystem 等）内 addNotice 的英文串，**及相关测试断言同步改写**；
- `UnitDetailDialog` 标签（见 R2）；
- `TopBar`（ROUND/GOLD/LV/EXP 格式，含 `statusText` 纯函数与 TopBarTextTest 断言）；
- `BattleRenderer`：SELL 区 "SELL"、`SHOPPING_HINT`（"DRAG UNITS TO BOARD…"——原"默认字体无 CJK 字模"注释已过时，Fusion Pixel 已入库）；
- `BattleHud`：×1/×2 变速、投降（SURRENDER）、计时条标签；
- `ShopBar`：REFRESH / EXP 4G 按钮文案。
- **术语表**：planner 按 GDD §术语拟定全表（生命/攻击/护甲/攻击速度/射程/移动速度/费用/等级/经验/金币/轮次/羁绊/种族/职业…）落入计划文档供用户评审后执行。
- **CJK 降级口径**：Fusion Pixel 缺文件回退内置字体时无 CJK 字模——planner 定降级表现（要求：不炸；乱码方块可接受或 ASCII 降级，二选一并说明）。

## 3. 约束与验收方向

- Java 标识符全英文；TDD（文案格式化纯函数、悬停状态机、desc 字段解析校验均 headless 可测）；单文件上限 800 行；不引入新 RNG 消耗点。
- 验收方向：悬停可先查后买（棋盘+商店）；详情弹窗含技能/羁绊描述且无遮挡；通知与全部 UI 文案中文且术语一致；564+ 测试全绿零回归；lwjgl3 手验项随计划给出。
